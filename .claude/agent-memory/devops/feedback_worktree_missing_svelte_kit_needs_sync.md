On SELF-nodemailer-audit-fix (2026-09-08/09), after `cp -a`-copying `api/node_modules`
into a fresh worktree per [[reference_worktree_path_moved]] and the Frontend
memory note on symlink breakage, `npm test` (vitest) still failed at startup with:

```
AggregateError: Failed to initialize projects...
[RESOLVE_ERROR] Could not resolve 'node:module' in \0rolldown/runtime.js
  ...Tsconfig not found
```

This looked like a broken dependency-optimization/environment issue, but the
same command ran clean (203/208 files, 2628/2651 tests passed) in the main
checkout's `api/` at the same instant — proof it was worktree-specific, not a
real regression from the change under test.

**Cause:** `api/tsconfig.json` has `"extends": "./.svelte-kit/tsconfig.json"`.
`.svelte-kit/` is gitignored (generated by SvelteKit's `sync` step, wired as
the `prepare` npm script) and does not exist in a freshly created worktree —
only copying `node_modules` isn't enough. Vite/rolldown's tsconfig resolution
failure surfaces as an opaque rolldown internal error, not a clear "file not
found," which is why this is easy to misdiagnose as a dependency-version or
node_modules-copy problem.

**How to apply:** in any fresh `api/` (or other SvelteKit-package) worktree,
after populating `node_modules`, run `npx svelte-kit sync` (or `npm run
prepare`) BEFORE `npm test` / `npm run check`. Confirn `.svelte-kit/` exists
(`ls .svelte-kit`) as a cheap precondition check when a startup error mentions
rolldown, tsconfig, or `node:module` resolution and the same command works
in the main checkout.
