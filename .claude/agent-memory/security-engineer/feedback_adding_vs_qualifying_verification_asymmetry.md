**When a claim ADDS something the addition gets checked; when it QUALIFIES something the qualifier
ships unchecked — and the qualifier is where the falsifiable content lives.** Never bound my doubt
to what the author happened to notice. Two SELF-256 instances below, both caught by reading past the
part that was offered for checking.

⚠ **A QUOTED PREMISE THE IMPLEMENTATION DOES NOT SATISFY — a fifth citation failure mode, and the
quotation is exact.** SELF-256: a loader header quoted `098` to justify its two-RPC shape —
*"they would still agree in two statements **in the same transaction**"* — and then claimed the
property was delivered. The quote was byte-exact, the elision legitimate, and the property (one
argument, one call site) genuinely WAS delivered. **What did not hold was the quoted sentence's own
qualifier:** the loader issues two statements in TWO transactions, a case the quoted sentence does
not reach, and the file went silent exactly there. **Pointer right, content right, extent right,
attachment right — and still defective, because the cited text carried a PREMISE and the citing text
answered only the conclusion.** How to apply: after verifying a quotation, read it once more asking
*"what does this sentence assume, and does the code assume it too?"* The tell is a quoted
conditional or prepositional qualifier (`in the same transaction`, `at or before`, `when X holds`)
followed by a gloss that addresses only the main clause. Related: [[sound-quote-false-gloss-drift]].

⚠ **A RESIDUAL HANDED TO ME AS SYMMETRIC USUALLY IS NOT — enumerate the interleavings before
grading it.** The same review's two-read residual was briefed as "the two can transiently desync."
Working the orders out: one produces harmless OVER-disclosure, the other produces **false
reassurance** (an incomplete chart under a banner saying nothing is outstanding). Only one direction
carries the finding, and naming it is what makes the accept-and-document disposition defensible
instead of hand-waving. **For any advisory/disclosure signal derived from a second read, ask which
interleaving tells the user "you're fine" when they are not** — and note that ordering the reads can
convert one race without closing another, so "order them" is a partial fix that must be sold as
partial. Same family as [[replacement-control-name-the-losing-side]].

⚠ **AND MY OWN QUALIFIER WAS THE UNCHECKED ONE — analogy is not derivation.** Same review, one turn
later: I offered option B ("order the two reads") with the qualification that it "closes the
classification race but NOT the ingest-arrival race." **Wrong.** I had DERIVED the classification
race step by step, then EXTRAPOLATED the arrival race by analogy. The analogy held for *"the item is
missing from the bars"* and broke on *"and the count fails to flag it"* — which is the half that
makes a race harmful. A newly-arrived unclassified item is excluded from the bars in BOTH orders
anyway, so one order is ordinary page staleness and the other is correct over-disclosure; neither is
harmful. **The tell: I stated the derived half and the analogized half in one sentence, at the same
confidence.** Mark which half was walked. **And a qualification attached to a REJECTED option still
ships as fact** — it gets relayed to whoever might revive that option later, so it earns the same
verification as the recommendation. Caught only because the implementing agent shipped the
UNqualified claim and I checked their wording against my own.
