### E8 — The SELF-259 replace-all is ONE SECURITY INVOKER plpgsql function, serialized by a `FOR UPDATE` lock on the owner's schedule row; Decision 18's "under SERIALIZABLE" is realized that way and amended to say so · TEAM-LEAD RULING UNDER DELEGATION · 2026-09-03
Backend measured the transport limit `045` already records: PostgREST runs each `.rpc()` / `.from()` as its own transaction and cannot hold a client-side `BEGIN SERIALIZABLE`; and `SET TRANSACTION ISOLATION LEVEL` cannot be issued inside a function body (the calling SELECT has already taken its snapshot). So the atomic replace-all body is **`pfin.fn_tax_bracket_schedule_replace_all(p_schedule_id bigint, p_tax_year smallint, p_schedule_type pfin.tax_schedule_type_enum, p_standard_deduction numeric, p_tax_balance_prior_year numeric, p_rows jsonb) returns void`**, `security invoker`, `set search_path = ''`, `volatile`, EXECUTE revoked from PUBLIC and granted to `authenticated`, **no tenant parameter** (R4 rider 4; Sec D-2). Its first statement locks the caller's own schedule row — `select id from pfin.tax_bracket_schedule where id = p_schedule_id for update` under RLS, which refuses (zero rows → RAISE) for another tenant's or an absent schedule — so two concurrent replace-alls on one schedule cannot interleave their DELETE/INSERT pairs. ⚠ **Rationale corrected 2026-09-03 after Architect struck the lock on a scratch copy and ran the race:** the schedule does NOT end as A ∪ B on this pair — the zero-floor fence puts `bracket_floor 0` in every non-empty set, so `unique (schedule_id, bracket_floor)` converts the union into (i) a second-writer abort on a duplicate-key error naming a constraint unrelated to the cause, or (ii) when the second caller sends an EMPTY set to clear the schedule, **no error and a silent lost update** (the schedule keeps the first caller's rows). The lock removes both; the ruling stands; the build-side texts (`101` header, function comment, D18 amendment) carry the measured modes. A header asserting the unreachable union would have sent QA's battery hunting a failure this schema cannot produce. Then DELETE the schedule's rows, INSERT `p_rows` (each element `{bracket_floor, bracket_rate}`), UPDATE the scalars, and let the deferred set fence and the matched-tenant fence fire at commit. Schedule CREATION is an ordinary INSERT under RLS (an empty schedule is legal per `101`); the function refuses an absent schedule rather than creating one. **Losing side:** true SERIALIZABLE isolation would also catch write skew across *different* schedules of one user, which nothing on this surface reads across, so the lock's narrower guarantee covers every hazard the surface has; and a `default_transaction_isolation` change on the PostgREST role would be global and untestable per surface. **ADR-011 Decision 18 gets a dated amendment paragraph** (Architect, in the SELF-259 PR) recording that "replace-all under SERIALIZABLE" is realized as this function + row lock, with the transport reason — a downstream register cannot carry an amendment to a lock. Sec joint-review reads the function.
