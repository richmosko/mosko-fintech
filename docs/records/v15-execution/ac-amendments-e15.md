## (a) SELF-366 — A10. On-demand monthly-report generation write path — ADD

> 9. **At most ONE live `draft` per `(users_id, target_month)` — RULED at E15, DB-fenced.** `108` carries a partial unique index `(users_id, target_month) WHERE generation_status = 'draft'`, the sibling of the existing `… WHERE generation_status = 'final'` fence. **This endpoint is idempotent on an existing draft: when a `draft` row already exists for the target month, it returns THAT row and inserts nothing** — "Generate" on a month that already has a draft OPENS the draft. ⚠ **The falsifying case is silent commentary loss, not a duplicate listing:** the user opens the editor on draft #1 (tab A), clicks Generate again (tab B) → draft #2; tab A's Save lands on #1 (still `draft`, the immutability trigger permits it), P4 finalizes #2 with four blank sub-sections. An app-only "check then insert" is exactly the control that loses this race, which is why the fence is at the DB and the endpoint's insert is expected to be *refused* there in the race, then resolved by re-reading the existing draft. Orphan drafts would also persist forever (A1 item 6(a) blocks DELETE). **Losing side recorded at the ruling:** one more partial index on an audit-class table, and a second `unique_violation` branch in this endpoint.
> 10. **Regenerate is a `final`-only affordance on this path.** A `draft` already composes LIVE through A3 (P2 item 2), so "regenerate a draft" has nothing to produce; the INSERT-new-version + `final → superseded` pair (A1 item 6(ii)) is issued **only** when the month's current row is `final`. ⚠ A request to regenerate a month whose current row is `draft` is answered by item 9 (open the draft), never by a second INSERT.
> 11. **QA (P10):** (i) two concurrent Generate calls for the same month yield ONE `draft` row and both callers receive its id; (ii) INSERT of a second `draft` for `(users_id, target_month)` submitted directly through PostgREST is refused by the DB — the same fact the app relies on, provable without the app; (iii) Regenerate against a `draft` month inserts nothing.

## (a) SELF-357 — P5. §2.6.3.b on-demand UI + pending queue — ADD

> 8. **The listing and the pending queue are keyed per `target_month`, never per row.** One listing entry per month (the `final` row, or the month's single live `draft`); one pending item per month. ⚠ Superseded rows are history, not entries — a month regenerated twice is still ONE entry in the listing. ⚠ SELF-365's N = 2 counts **months**, not rows (its AC wording is PM's, re-worded at the amendment batch).
> 9. **"Generate monthly report" on a month that already has a `draft` OPENS that draft (A10 item 9) — the CTA never produces a second draft.** Copy (PM) when the selected month already has a draft: button label becomes *"Continue {Month YYYY}"*; no confirmation dialog, because nothing is written.
> 10. **Regenerate is offered ONLY on a `final` report (A10 item 10).** On a `draft` month the affordances are P4's — *"Write commentary"* / *"Skip commentary and finalize"* — and no Regenerate control renders. ⚠ P5 item 4's copy (*"The current report is replaced…"*) therefore describes the `final → superseded` case only; do not reuse it for a draft.

## (b) SELF-355 — P3. §2.6.2.b commentary editor UI — ADD (Sec N-5 riders)

> 10. **Length bound: 4000 characters per sub-section (PM ruling 2026-09-05; A1's CHECK, Sec N-5).** Each text area shows a live counter beneath it — copy (PM): *"{n} / 4000"* — and **Save draft** and **Finalize {Month YYYY}** are disabled while any sub-section exceeds the bound, with the counter styled as an error and the copy *"Over the 4000-character limit for {Cat}."* ⚠ The 400 from item 6's Zod bound is a **fence, not a UX path**: a user who reaches it has bypassed the disabled control, and the app treats it as such (generic error, no partial write). **Losing side (PM's, recorded at the number):** 2000 would have tracked the typical month more tightly at the cost of refusing the heavy month (per-position list, tax-loss plan) inside the draft window; 8–10k would have been a memory fence with no product meaning.
> 11. **The mirror rule — the client counts CODE POINTS, so the same value is refused at both layers.** Postgres `length()` counts code points; JS `.length` counts UTF-16 code units, so an emoji is 1 at the DB and 2 in the browser. **The Zod bound and the live counter use `Array.from(s).length` (code points), never `.length`**, so that the value refused at the DB and the value refused at the app are the *same* value (Sec N-5's catch criterion: one over is rejected at both, and the two layers can disagree only by construction error). ⚠ **The falsifying case is a 3,999-code-point body containing five astral characters:** on `.length` it is 4,004 and the app refuses what the DB accepts — a *tighter* app layer, so not a hole, but not "the same number" either, and the counter would tell the user 4,004 while the DB says 3,999. Line breaks count as one character each (`\n`); the client normalizes `\r\n` → `\n` before counting and before submit.
> 12. **QA (RT-11 leg, extends item 9):** (i) a 4,000-code-point body saves; 4,001 is refused 400 by the app AND refused by the DB when submitted directly through PostgREST; (ii) a body of 3,996 ASCII + 4 astral characters (4,000 code points, 4,004 UTF-16 units) is **accepted** by both layers — the leg that fails if anyone reverts to `.length`; (iii) the counter renders 4,000 for case (ii).

## (d) SELF-348 — A4 AC 4b + sitting-log R2.2 — CORRECTION (Sec R-1 at PR #634, ruling E25)

The literal *"the interception handler recorded two aborts"* is STRUCK. Measured: Chromium refuses the `file:///proc/self/environ` iframe under its own local-resource policy before any request event fires, so only the `http://169.254.169.254/` vector reaches interception. The criterion's rationale (a failed fetch and a blocked fetch render identically) is discharged by three legs, not a count: a LOCALLY REACHABLE `http://` positive control that the handler aborts; `file://` attributed separately to Chromium's policy (console "Not allowed to load local resource"), never folded into the count; and `data:` NOT aborted as the discriminating negative control. ⚠ P10's battery must be written to these three legs; an `abortedCount === 2` assertion would red against correct behaviour, and the tempting repair for that red is to weaken the fence. Sec's full replacement wording: `docs/records/v15-execution/self348-sec-review.md` § R-1.
