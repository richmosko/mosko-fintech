Three parts: **accounts → `.env` → run the scripts.** Full rationale (MEASURED findings, incident history, Sec dispositions, design history) for every row below lives in the cited script's own header comment, in [`DECISIONS.md`](../DECISIONS.md), or in the frozen archive: [`docs/archive/deployment-runbook-rationale-2026-09-20.md`](archive/deployment-runbook-rationale-2026-09-20.md). ## Part 2 — `.env`

One file: [`scripts/provision.env.example`](../scripts/provision.env.example) — the **complete, CI-fenced contract** (`fence-operator-env-template.sh` fails the build if a script reads a name this file doesn't list). Copy it to a gitignored `.env` at the repo root and fill in the values Part 1 produced.

- **Operator-provided** (Part 1's values): `HETZNER_API_TOKEN`, `COOLIFY_ADMIN_EMAIL`/`_NAME`/`_PASSWORD` (human-chosen, not generated), `SMTP_PASS`/`SMTP_ADMIN_EMAIL`/`SMTP_SENDER_NAME`, `CI_MIGRATE_SSH_PUBKEY` (path to a keypair — see Part 3), `PDF_WORKER_SIGNING_KEY`/`WORKER_ADMISSION_SHARED_SECRET` (`openssl rand -hex 32`), `DISCORD_WEBHOOK_URL`, `FMP_API_KEY`, `BLS_API_KEY`, `PLAID_CLIENT_ID`/`PLAID_SECRET`, `SIMPLEFIN_TOKEN`.
- **Not yet needed — do not mint speculatively:** `PORKBUN_API_KEY`/`PORKBUN_SECRET_KEY` — skip until [BACKLOG §7.36 item 72](../BACKLOG.md) lands (Sec: a registrar credential is DNS control, which is cert-issuance control, which is an MITM surface — don't hold one with no consumer). Step 9 (DNS) stays a console action until then.
- **Script-written — leave blank, do not fill in by hand:** `BOX_IP`, `MIGRATOR_SERVICE_UUID`, `SUPABASE_STACK_UUID`, `MIGRATOR_TASK_UUID`, `APP_UUID`, `ETL_UUID`, `PDF_RENDER_UUID`, `PROVIDER_SYNC_UUID` — all seven UUIDs are written by `scripts/provision-vps.sh --apply` / `scripts/record-coolify-uuids.sh --apply` in Part 3.
- **Named but never set here** (box-generated or script-minted; zero effect if you set them anyway): `COOLIFY_API_TOKEN`, `JWT_SECRET`, `SUPABASE_SERVICE_ROLE_KEY` (minted LAST by `scripts/mint-supabase-jwt-keys.sh` as a JWT signed from `JWT_SECRET` — never `openssl rand`; the template's own placeholder says so) — see the template's own "BOX-GENERATED" block for why.
- `PFIN_DB_PASSWORD` is **not** in `.env` at all — generated by `scripts/db-role-handoff.sh` at Part 3's role-handoff step.

## Part 3 — Run

Every step: preflight first (no flag), read the plan, then `--apply`. Stop on non-zero exit. Scripts are idempotent — re-running a done step reports "already satisfies."

Row order follows original section order, corrected twice against a real proven sequence (stage A, `standup-log.md` §7.1) rather than the document's own numbering: **every deploy waits until every env write for that resource has already landed** — no `deploy-app.sh` call runs before its target's non-secret env, secrets push, and (for `app`) the JWT mint have all completed, because none of this repo's compose files default-guard a missing var (no `${VAR:?}`), so an early deploy boots with silently empty secrets. This moved `db-role-handoff.sh` (§6.1/§6.2, fails closed on a missing resource) to after resource creation, and moved §6.9's PGRST-exposure flip earlier — `smoke-pfin-exposure.sh` (step 13) expects `pfin` already exposed, per its own header. **Every BY-HAND row is graded strictly**: "nobody scripted it yet" is a defect, cited to the BACKLOG item that books the fix — only genuine credential/account/decision moments stay unbooked.

**🔒 §4.1's TimeZone-pin verification (Sec-gated CI anchor — this exact block is fenced by `scripts/ci/check-tz-sweep-identical.py`, kept token-identical to (T3) in `supabase/tests/01_session_timezone.sql`; do not reword):**
```sh
psql "$PROD_DB_URL" -Atc \
  "select r.rolname, d.datname, c as setting
     from pg_db_role_setting s
     join pg_roles r on r.oid = s.setrole
     left join pg_database d on d.oid = s.setdatabase
     cross join lateral unnest(s.setconfig) as c
    where s.setrole <> 0
      and c ilike 'timezone=%'"
```
Required: zero rows. Run after step 3, before step 18. `PGRST_DB_SCHEMAS` ruled literal ([ADR-023](../DECISIONS.md#adr-023)): `PGRST_DB_SCHEMAS=public,graphql_public,pfin`.

**Done looks like:** the `app` URL answers over TLS; steps 16/18's smoke gate is fully green; Discord received at least one deploy notification.

Until it lands, every script above is preflight-safe and idempotent — re-run from the step that failed; confirm its preflight output shows the prior steps already satisfied before passing `--apply`.
