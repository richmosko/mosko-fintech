# Deployment Runbook — V1 greenfield stand-up

**Owner:** DevOps. 🔒 = security-sensitive (Sec joint-review gates it). Production is Coolify on Hetzner cax21 — no other deploy surface. Three parts: **accounts → `.env` → run the scripts.** Full rationale (MEASURED findings, incident history, Sec dispositions, design history) for every row below lives in the cited script's own header comment, in [`DECISIONS.md`](../DECISIONS.md), or in the frozen archive: [`docs/archive/deployment-runbook-rationale-2026-09-20.md`](archive/deployment-runbook-rationale-2026-09-20.md). This file states the execution path only.

## Part 1 — Accounts

Create these before starting. Coolify and Supabase need **no account** — both are self-installed by the scripts in Part 3.

| Provider | What to create | What you copy into `.env` | Where |
|---|---|---|---|
| **Hetzner Cloud** | Account + payment method; an API Token (Read & Write permission) | `HETZNER_API_TOKEN` | console.hetzner.cloud → project → Security → API Tokens |
| **Domain registrar** (currently **Porkbun**, confirmed live via `dig NS pfindash.com`) | Access to DNS records for the production domain | *nothing* — no script reads a registrar API credential; DNS records are set by hand (Part 3) | porkbun.com |
| **Resend** (V1 default SMTP; SES is the documented alternative — [`docs/email-smtp-runbook.md`](email-smtp-runbook.md)) | Account + a verified sending domain | `SMTP_PASS` (API key) | resend.com |
| **Plaid** (primary provider) | Developer account; sandbox keys (for CI, separate from this `.env`) + production API access | `PLAID_CLIENT_ID`, `PLAID_SECRET` | dashboard.plaid.com |
| **SimpleFIN** (fallback provider) | Bridge access token | `SIMPLEFIN_TOKEN` | bridge.simplefin.org |
| **Financial Modeling Prep (FMP)** | API key | `FMP_API_KEY` | financialmodelingprep.com |
| **BLS (Bureau of Labor Statistics)** | Free API registration | `BLS_API_KEY` | bls.gov/developers |

| **GitHub** | Already have repo admin access. Also needed: an Actions secret, an Actions variable, and an Environment (all set in Part 3, not here) | *(no `.env` value — these live in GitHub, not the box)* | this repo's Settings |

## Part 2 — `.env`

One file: [`scripts/provision.env.example`](../scripts/provision.env.example) — the **complete, CI-fenced contract** (`fence-operator-env-template.sh` fails the build if a script reads a name this file doesn't list). Copy it to a gitignored `.env` at the repo root and fill in the values Part 1 produced.

- **Operator-provided** (Part 1's values): `HETZNER_API_TOKEN`, `COOLIFY_ADMIN_EMAIL`/`_NAME`/`_PASSWORD` (human-chosen, not generated), `SMTP_PASS`/`SMTP_ADMIN_EMAIL`/`SMTP_SENDER_NAME`, `CI_MIGRATE_SSH_PUBKEY` (path to a keypair you generate — see Part 3), `SUPABASE_SERVICE_ROLE_KEY`/`PDF_WORKER_SIGNING_KEY`/`WORKER_ADMISSION_SHARED_SECRET` (`openssl rand -hex 32`), `DISCORD_WEBHOOK_URL`, `FMP_API_KEY`, `BLS_API_KEY`, `PLAID_CLIENT_ID`/`PLAID_SECRET`, `SIMPLEFIN_TOKEN`.
- **Script-written — leave blank, do not fill in by hand:** `BOX_IP`, `MIGRATOR_SERVICE_UUID`, `SUPABASE_STACK_UUID`, `MIGRATOR_TASK_UUID`, `APP_UUID`, `ETL_UUID`, `PDF_RENDER_UUID`, `PROVIDER_SYNC_UUID` — all seven UUIDs are written by `scripts/provision-vps.sh --apply` / `scripts/record-coolify-uuids.sh --apply` in Part 3.
- **Named but never set here** (box-generated, zero effect if you set them anyway): `COOLIFY_API_TOKEN`, `JWT_SECRET` — see the template's own "BOX-GENERATED" block for why.
- `PFIN_DB_PASSWORD` is **not** in `.env` at all — generated by `scripts/db-role-handoff.sh` at Part 3's role-handoff step.

**§4.1's TimeZone-pin verification (Sec-gated CI anchor — this exact block is fenced by `scripts/ci/check-tz-sweep-identical.py`, kept token-identical to (T3) in `supabase/tests/01_session_timezone.sql`; do not reword):**
```sh
psql "$PROD_DB_URL" -Atc \
  "select r.rolname, d.datname, c as setting
     from pg_db_role_setting s
     join pg_roles r on r.oid = s.setrole
     left join pg_database d on d.oid = s.setdatabase
     cross join lateral unnest(s.setconfig) as c
    where s.setrole <> 0
      and c ilike 'timezone=%'"
```
Required: zero rows. Run after step 3, before step 12. `PGRST_DB_SCHEMAS` ruled literal ([ADR-023](../DECISIONS.md#adr-023)): `PGRST_DB_SCHEMAS=public,graphql_public,pfin`.

**Done looks like:** the `app` URL answers over TLS; step 12's smoke gate is fully green; Discord received at least one deploy notification.

**Resuming after a stop:** no `--from <step>` flag exists yet (that's `scripts/provision.sh`'s own future job — not yet built, this table is its spec). Every script above is preflight-safe and idempotent — re-run from the step that failed; confirm its preflight output shows the prior steps already satisfied before passing `--apply`.

- The GitHub Environment reviewer click — recurs on **every** migrator trigger fire from step 14 onward, by Sec's own ruling; not a setup-only step, and not something item 73's script covers.
