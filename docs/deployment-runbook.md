## Part 2 — `.env`

One file: [`scripts/provision.env.example`](../scripts/provision.env.example) — the **complete, CI-fenced contract** (`fence-operator-env-template.sh` fails the build if a script reads a name this file doesn't list). Copy it to a gitignored `.env` at the repo root and fill in the values Part 1 produced.

- **Operator-provided** (Part 1's values): `HETZNER_API_TOKEN`, `COOLIFY_ADMIN_EMAIL`/`_NAME`/`_PASSWORD` (human-chosen, not generated), `SMTP_PASS`/`SMTP_ADMIN_EMAIL`/`SMTP_SENDER_NAME`, `CI_MIGRATE_SSH_PUBKEY` (path to a keypair — see Part 3), `PDF_WORKER_SIGNING_KEY`/`WORKER_ADMISSION_SHARED_SECRET` (`openssl rand -hex 32`), `DISCORD_WEBHOOK_URL`, `FMP_API_KEY`, `BLS_API_KEY`, `PLAID_CLIENT_ID`/`PLAID_SECRET`, `SIMPLEFIN_TOKEN`.
- `COOLIFY_ADMIN_EMAIL`/`_NAME`/`_PASSWORD` are required in `.env` on **every** `provision.sh` run, not just the first — `provision.sh`'s own `.env` preflight (Part 3) checks these names are present before anything else runs, even though `provision-vps.sh`'s own admin-account bootstrap is itself one-time-consumed (a no-op on a box that already has the Coolify admin created). Leave them filled in; do not remove them after the first successful run.
- **Not yet needed — do not mint speculatively:** `PORKBUN_API_KEY`/`PORKBUN_SECRET_KEY` — skip until [BACKLOG §7.36 item 72](../BACKLOG.md) lands (Sec: a registrar credential is DNS control, which is cert-issuance control, which is an MITM surface — don't hold one with no consumer). - **Script-written — leave blank, do not fill in by hand:** `BOX_IP`, `MIGRATOR_SERVICE_UUID`, `SUPABASE_STACK_UUID`, `MIGRATOR_TASK_UUID`, `APP_UUID`, `ETL_UUID`, `PDF_RENDER_UUID`, `PROVIDER_SYNC_UUID` — all seven UUIDs are written by `scripts/provision-vps.sh --apply` / `scripts/record-coolify-uuids.sh --apply` in Part 3.
- **Named but never set here** (box-generated or script-minted; zero effect if you set them anyway): `COOLIFY_API_TOKEN`, `JWT_SECRET`, `SUPABASE_SERVICE_ROLE_KEY` (minted LAST by `scripts/mint-supabase-jwt-keys.sh` as a JWT signed from `JWT_SECRET` — never `openssl rand`; the template's own placeholder says so) — see the template's own "BOX-GENERATED" block for why.
- `PFIN_DB_PASSWORD` is **not** in `.env` at all — generated by `scripts/db-role-handoff.sh` at Part 3's role-handoff step.

## Part 3 — Run

One script. `.env` is Part 2 — copy `scripts/provision.env.example` to `.env` first.

```sh
scripts/provision.sh --dry-run   # preflight only, touches nothing; exit 0 or exit 3 -- see below
scripts/provision.sh             # the real run
```
Neither needs a `BOX_IP=` prefix — step 1 discovers/creates the box and writes `BOX_IP` into `.env` itself. `--dry-run` prints one line per step: `VERIFIED`/`SKIPPED`/`MANUAL` (each `(dry-run)`), `BLOCKED-BY <step>` (this step's own preflight failed because an *earlier* step's output does not exist yet — expected on a partially-provisioned box, since `--dry-run` never applies anything; not a defect), or `would likely fail` (a genuine, independent failure). Exit 0 means every step cleared or was legitimately blocked by one not yet applied; **exit 3 means at least one step would likely fail for its own reason** — the summary names how many and each `rc=`; investigate those before the real run. `--list` prints the plan without running it.

**Done looks like:** every step through `remaining-checks`/`discord` reads `VERIFIED`/`SKIPPED` in the printed summary table, `pfin-app` answers over TLS, and `cutover` itself reads `VERIFIED` (exit 0) — see below.

**If it stops:** it prints `resume: scripts/provision.sh --from <step>` plus the summary so far. Fix that step, re-run that line.

**Four unavoidable manual moments:**
1. **Account creation** (Part 1) — before running; no script creates an account.
2. **DNS repoint, behind `--confirm-cutover`** — the apex A repoint (`dns`) is the user-visible go-live switch, gated the same as `cutover` below (Sec F-6, PR #849 review): neither runs without `--confirm-cutover`. `dns` proceeds normally once passed (on this deployment it already points at the box, so it reads VERIFIED/no-op — the gate is structural, not a response to a pending change). Tearing down an incumbent stack (BY HAND, a one-way F/CTO call, never scripted, never bundled into a bare `--apply`) — `cutover` refuses without `--confirm-cutover`; once passed, it VERIFIES the tear-down directly against the Hetzner API (project holds exactly one server, named `pfin-prod-1`) rather than stopping unconditionally.
3. **GitHub Environment reviewer approval** — not a `provision.sh` step (its `ci-keypair`/`github-ci` steps only wire the gate up; `db-bootstrap` applies the *initial* migration directly over SSH, bypassing it). Recurs on every **future** `ci-migrate` CI fire, Sec-ruled, out of scope for any script. ⚠ A fire-and-poll mode inside `provision.sh` (dispatch, then print/wait on the review URL instead of pointing at the Actions tab) was scoped this pass and deliberately deferred — too risky to build without a live box to verify against — [BACKLOG §7.36 item 73](../BACKLOG.md) carries the follow-up.
4. **`remaining-checks`'s email-confirmation round-trip** (QA, `scripts/smoke-remaining-checks.sh`, [BACKLOG §7.36 item 81](../BACKLOG.md)) — CA-7/TZ-1/RLS-isolation are fully scripted, and auth-login's login-page/signup-validation/Resend-send-acceptance sub-checks run automatically once `pfin-app` carries a public domain, but *following the real link a confirmation email carries and confirming the session actually establishes* is not: it requires reading an arbitrary recipient's real inbox, which no credential this repo holds grants, and scripting around that would mean creating a real account against production on every run. `remaining-checks` therefore caps at MANUAL (not VERIFIED) whenever a domain exists, even with every automatable sub-check passing — confirm the round-trip by hand, then resume.

**🔒 §4.1's TimeZone-pin verification (Sec-gated CI anchor — this exact block is fenced by `scripts/ci/check-tz-sweep-identical.py`, kept token-identical to (T3) in `supabase/tests/01_session_timezone.sql`; do not reword):**
```sh
psql "$PROD_DB_URL" -Atc \
  "select r.rolname, d.datname, c as setting
     from pg_db_role_setting s
     join pg_roles r on r.oid = s.setrole
     left join pg_database d on d.oid = s.setdatabase
     cross join lateral unnest(s.setconfig) as c
    where s.setrole <> 0
      and c ilike 'timezone=%'"
```
Required: zero rows. Run after `db-bootstrap`, before `remaining-checks` (`provision.sh`'s own `remaining-checks` step names this query; it is one of the four checks that step still reports BY-HAND). `PGRST_DB_SCHEMAS` ruled literal ([ADR-023](../DECISIONS.md#adr-023)): `PGRST_DB_SCHEMAS=public,graphql_public,pfin`.
